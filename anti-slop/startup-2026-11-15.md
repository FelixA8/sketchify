## Excalidraw source findings

Inspected the official repository's `master` source on 2026-11-15. This is source analysis, not a live startup timing measurement.

- [LayerUI.tsx](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/components/LayerUI.tsx) renders its scene-loading indicator only when `isLoading` is true, passing a 250 ms delay. [LoadingMessage.tsx](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/components/LoadingMessage.tsx) returns nothing until that delay expires. If initialization finishes sooner, the component unmounts without displaying a spinner or message. Excalidraw retains a loader for slower scene restoration.
- [App.tsx](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/components/App.tsx) restores the scene and clears `isLoading` before starting its font prewarm. It does not await font loading to complete scene initialization. [Fonts.ts](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/fonts/Fonts.ts) invalidates affected text shapes and triggers an update after fonts load.
- [excalidraw-app/index.html](https://github.com/excalidraw/excalidraw/blob/master/excalidraw-app/index.html) applies the saved theme in the document head to reduce a white flash, registers UI font CSS early, and starts with an empty application root. Its static HTML does not contain a “Loading Excalidraw” splash screen.

## Sketchify change

The old Next.js dynamic boundary displayed “Loading Sketchify…” while awaiting both the whiteboard module and the handwriting font. The message represented local asset initialization, not a network connectivity check.

The page now directly imports the whiteboard and pre-renders its real canvas and controls into the static document. Browser APIs execute in mounted controllers and effects. Initial store creation no longer reads viewport globals, and context-menu platform labels have a stable server snapshot for hydration.

The existing local font preload is retained. Font prewarming now runs after mounting, without gating the interface. Font completion refreshes text geometry, bound labels, connectors, and the editing baseline without creating a scene undo step. A refresh waits for any active pointer gesture to finish. Undo/redo remeasures restored text. Failed fonts retain usable fallback rendering; disposed controllers ignore late promises.

No startup spinner, delayed splash, artificial wait, or skeleton replaces the removed message. Actual image decoding/error placeholders and storage error recovery remain available.

## Follow-up: canvas-colored startup

The user requested that the initial flash match the canvas background in dark mode. A synchronous inline head script now restores appearance from the existing scene storage key before the body is parsed. Its self-contained appearance function is also used after hydration, so both phases use the same color resolution: #121212 for dark mode, or a validated saved canvas color for light mode. It applies the root class, background, canvas CSS variable, native color scheme, and available theme-color metadata. Corrupt or inaccessible storage falls back without blocking startup.

The pre-rendered canvas no longer has a white inline color override; it inherits the document's restored canvas color. The HTML element tolerates the expected pre-hydration class/style changes. No new storage key, loading state, animation, or visual component is introduced.

- PASS: all 247 Node tests, lint, TypeScript, and production build.
